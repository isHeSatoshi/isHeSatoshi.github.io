HOW I WORK / 04 · TRY · COMPARE · WRAP · GROUND

How I work

Try the next model. Compare it head-to-head. Build the harness when the tooling gets in the way. Ground every claim.

Project types Inference · RAG · Agents · Evals · Hardware
Project stages Try a new model → Compare → Wrap with the right harness
Collaboration Independent lead · Hackathon teams · Co-builds
01. Try / Compare

Always trying the next model

New open-weight releases, new agentic harnesses, new inference runtimes. I run them on the same real input and see what actually changes.

  • Open-weight bench
  • Head-to-head
  • Notes on what breaks
Typical output An honest comparison, not a screenshot
02. Build / Wrap

Build the missing layer

When the model's behavior is interesting but the surrounding tooling isn't, I write the harness, the eval, the agent loop, or the inference path that lets it actually do something.

  • Agent harnesses
  • Inference paths
  • Eval suites
Typical output A working system the model can actually live in
03. Quantize / Distill

Make the model fit the box

Take a too-large or too-slow model and put it where it needs to run — GPTQ, AWQ, GGUF, knowledge distillation, custom kernels when the path is interesting.

  • GPTQ / AWQ
  • GGUF / llama.cpp
  • Distillation
Typical output The right model at the right cost on the right hardware
04. Ground / Loop

Ground the claims

Holdout design, anti-contamination canaries, deterministic harnesses, and numbers the code produces — not numbers I hand-typed.

  • Holdout sets
  • Regression gates
  • Auto-generated tables
Typical output Eval results you can re-run and verify
ABOUT @ISHESATOSHI

I'm an AI systems generalist. I care most about the boundary between the model and the systems that make it useful — and I'm comfortable jumping from research to infrastructure to a working prototype.

How I start I read the paper, the model's card, and the surrounding tooling. I pick the smallest honest experiment that compares architectures or harnesses on a real signal — not a synthetic one.

How I collaborate I write specs, harnesses, and visualizations. When the existing tooling gets in the way of what a model needs, I build the missing layer.
